# Phase 12 — CI/CD and rollback on Azure
Implement **only phase 12**. GitHub Actions: run tests on every push; on the main branch build both images, push to the container registry tagged with the commit SHA, update the `api` app and the two jobs, wait until the new revision is healthy. Authenticate with GitHub OIDC (federated credential) and a narrowly scoped identity; if the subscription forbids that, document the short-lived-credential alternative and never store permanent secrets. Demonstrate a rollback to the previous revision or image and record real commit and revision IDs. Database changes stay additive so a code rollback is safe.
